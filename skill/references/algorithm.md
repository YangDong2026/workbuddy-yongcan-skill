# 算法合同（开饭引擎）

本文件是「用餐」技能的唯一算法合同：固定菜单价目表、输入格式、九步点单算法、
输出格式与标准示例。执行任何用餐规划任务前必须通读本文件并逐条执行；
菜单、价格、保底款、升级路径、自检条款一律以本文件为准。

以下为合同正文：

口语归组参考（与网页版解析器同口径）：

  怕凉/不喝凉的 → 不喝冰饮组；“有人X”按 1 人计，“全员X”按全部计；
  过敏类信息一律写备注（上甜品前先看备注）。

【点单算法】（严格按序执行，每一步先列算式再写结果，全程记录金额流水）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
第1步 保底主食——先保证人人有饭吃：
  素食 V 人 → 蔬菜鸡蛋堡 12.0
  不吃辣 S 人 → 老北京鸡肉卷 13.5
  不吃猪肉 P 人 → 香辣鸡肉卷 12.5
  常规（其余）→ 香辣鸡肉卷 12.5
  保底合计 = 各组之和。若 B < 保底合计 → 直接转第9步"点不成"流程。

第2步 人手一瓶矿泉水（3元/人）：预算够就加；不够就跳过（喝免费柠檬水）。

第3步 忌口组升级（整组一起升，不拆散；忌口的人选择面窄，预算先紧着他们）：
  素食组：蔬菜鸡蛋堡12.0 → 素什锦炒饭15.0（+3.0/人）
  不吃辣组：老北京鸡肉卷13.5 → 新奥尔良烤鸡腿堡17.5（+4.0/人）
  不吃猪肉组：香辣鸡肉卷12.5 → 香辣鸡腿堡16.5（+4.0/人）
  每组升级前检查：加完这步总价 ≤ B 才升，否则保持原样并说明。

第4步 常规组升级：香辣鸡肉卷12.5 → 香辣鸡腿堡16.5（+4.0/人），同样先查预算。

第5步 饮料升级（人手一杯，按饮料桶）：
  常规（N-I-C 人）：矿泉水3.0 → 冰可乐(中)6.0（+3.0/人）
  不喝冰 I 人：矿泉水3.0 → 热豆浆7.5（+4.5/人）
  不喝咖啡因 C 人：矿泉水3.0 → 鲜榨橙汁9.0（+6.0/人）
  （若第2步矿泉水因预算被跳过，本步按饮品全价直接上，同样先查预算）

第6步 共享小食（仅 N≥3 时上；必须全员都能吃）：
  可选池按优先级：大薯条14 → 中薯条11 → 鸡米花12 → 洋葱圈10 → 玉米杯8 → 沙拉13；
  有人不吃辣 → 不上香辣鸡翅；有人素食 → 不上鸡米花和香辣鸡翅；
  有过敏类备注 → 只保留 玉米杯、蔬菜沙拉 两种最保守的小食。
  份数上限 = ⌈N/3⌉；从池子里按顺序"哪个买得起买哪个"，买到仂数用完
  或最便宜的也买不起为止。

第7步 豪华升级（仅当预算仍有富余，按序）：
  启动门槛：此时剩余预算 ≥ 5元 × 人数（人均还能再加一杯饮料的量级），
  不达标就直接收口——零头留作现场机动，不为凑单硬花。
  7a 主食豪华：不吃辣组/不吃猪肉组/常规组 → 深海鳕鱼堡18.0（素食组无豪华款，
      停在素什锦炒饭15.0）。
  7b 饮料豪华：常规组和不喝冰组（若能喝咖啡因）→ 热美式咖啡12.0；
      不喝咖啡因组不升（鲜橙汁已是顶配）。
  7c 甜品：葡式蛋挞（2只/份，10.0/份），份数上限 ⌈N/2⌉，买得起几份买几份；
      有过敏类备注时不上甜品（蛋奶交叉风险）。

第8步 收口自检（一票否决，逐条过，任何一条不过就回退重算）：
  ① 总价 ≤ 预算（一分都不能超）
  ② 不吃辣的人的主食辣度为0，共享小食同样不辣
  ③ 素食的人主食全素
  ④ 不吃猪肉的人主食不含猪肉
  ⑤ 不喝冰/不喝咖啡因的人的饮料对应合规
  ⑥ 主食份数 = N；饮料份数 = N（第2步矿泉水被跳过时除外：
     有人升级了饮料则核"≤ N"，没人升级则注明"全员免费柠檬水，不计价"）
  结余 = B − 总价。若结余 > B×20%，加一句："预算充裕，不为凑单硬点。"

第9步 "点不成"流程（B < 保底合计时）：
  如实报告：保底合计多少、差多少；给出最省点法（保底主食 + 免费柠檬水）；
  建议二选一：①预算补到保底合计；②减 1 人（可省下一份最贵组的保底主食）。
  N=1 时只建议补预算（单人单没有"减人"空间）。
