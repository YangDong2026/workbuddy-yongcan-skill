# 用餐 · 麦门点单引擎（麦当劳大赛版）

为「麦当劳 · 用餐赛道」打造的用餐 Skill，提供三大功能：

- **模式A 套餐推荐**：报个预算和口味，给出吃饱/吃好/豪华三档套餐方案；
- **模式B 麦门省钱**：报想吃的和预算上限，用替代/合并/免费项三招帮麦门弟子省出真金白银；
- **模式C 聚餐一键点**：报人数、预算、忌口，九步算法出一张全员适配的小票。

所有模式输出小票式方案：总价不超预算、忌口零违反、每笔花费有依据。

## 工作流程

按序执行：**接 MCP → 判模式 → 读合同 → 跑算法 → 出小票 → 记使用日志**。

### 0. 麦当劳 MCP 接入层（每次必跑）

**当前状态：已接入。** 端点 `https://mcp.mcd.cn`（streamable HTTP），服务器 `mcd-mcp v1.0.0`，开放 35 个工具。

1. 用 ToolSearch 检索麦当劳 MCP 工具（关键词：`麦当劳`、`mcdonalds`、`mcd`、`麦门`、`菜单`、`优惠`、`点餐`）。
2. **有可用 MCP 工具（已接入时的标准链路，按序调用）**：
   - `query-nearby-stores`（city + keyword，searchType=2）→ 拿 `storeCode`
   - `query-meals`（storeCode / orderType=1 / beType=1）→ 拿该店**当前时段**实时菜单与价格
   - `list-nutrition-foods` → 官方营养库（160 条，按餐品名关联千卡与蛋白）
   - `available-coupons` → 用户可领券，印在小票上
   - `calculate-price`（items: `[{productCode, quantity}]`）→ **真价核验**，把小票合计与官方返回逐分比对
   - 每次调用把「工具名 / 入参 / traceId / 结果」追加到 `references/mcp-usage-log.md`；小票底部打印调用链与 traceId
3. **无可用 MCP**：用离线合同菜单执行（或直接跑 `cli/yongcan_cli.py`），小票顶部标注 `（离线菜单模式）`，不虚构价格与调用记录；同时提示接入方法：
   - mcp.mcd.cn 手机号登录 → 右上角「控制台」→「激活」申请 MCP Token；
   - WorkBuddy 左侧【专家·技能·连接器】→【连接器】→ 右上角【自定义连接器】→【配置MCP】，粘贴：
     `{"mcpServers":{"mcd-mcp":{"type":"streamablehttp","url":"https://mcp.mcd.cn","headers":{"Authorization":"Bearer <你的Token>"}}}}`
   - 保存后回到【自定义连接器】将 mcd-mcp【启用】，本技能即自动切换实时菜单。

**接入后的三条硬规矩（实测踩出来的，不可违反）：**

- **菜单分时段**：每次运行都重新 `query-meals`，禁止复用上一次的菜单缓存（09:43 只有早餐 96 品，午晚市不同）。
- **套餐不与单品混算**：套餐 `currentPrice` 常为促销价（如 17.9，原价 29.9），`calculate-price` 不带 `roundList` 会按原价计。出单只用**单品组合**，保证本地合计与官方计价逐分对齐；若用户指定套餐，须先 `query-meal-detail` 取 `roundList` 再计价，并标注"套餐价以下单页为准"。
- **营养不估不编**：营养库按餐品名精确匹配，命中率约 22%（套餐/组合类多未收录）。未命中就写「未收录」，禁止用相似品项估算或用离线菜单千卡顶替。

### 1. 判定模式

按用户原话路由，拿不准时按 C 处理（C 是本技能的本体）：

| 用户话术特征 | 模式 |
| --- | --- |
| "推荐个套餐" / 只报预算+口味 / 提"减脂·低卡·管饱·热量" | A 套餐推荐 |
| "帮我省""怎么便宜""想省点" / 报想吃的+预算上限 | B 麦门省钱 |
| 报了人数（N≥2）或说"团建/聚餐/团队/大家" | C 聚餐一键点 |

### 2. 读算法合同（必读）

通读 [references/algorithm.md](references/algorithm.md) 全文后再动手。菜单价目表（13 主食 / 8 小食 / 7 饮料）、保底款、升级路径、九步算法、自检条款与输出格式均以该合同为准，**严禁虚构品项、改价或跳步**（接入 MCP 后以 MCP 实时数据替代合同菜单，算法与铁律不变）。

四条铁律（合同内有完整条款）：

1. 总价不超预算，一分都不能超；
2. 忌口零违反，含共享小食与甜品（过敏备注一票否决甜品）；
3. 收口自检硬约束逐条过，任何一条不过即回退重算；
4. 结余不硬花：豪华升级启动门槛 = 剩余预算 ≥ 5 元 × 人数，不达标直接收口。

### 3A. 模式A · 套餐推荐

- 输入：预算 B（默认按 1 人）、口味偏好（辣/不辣/随便）、**热量偏好（轻食/随意/管饱）**、饭点（早/午/下午茶/晚/夜宵，未报按午餐）。
- 主食 + 小食 + 饮料各选其一，组成"单 + 套"结构，给 **三档方案**：
  - **吃饱档**（约 0.6×B）：保底款组合，管饱为上；
  - **吃好档**（约 0.85×B）：升级款组合，口感优先；
  - **豪华档**（≤ B）：顶配组合，花满不超。
- **热量口径（赛题要求的"按热量配"）**：每档标注合计千卡（按合同菜单千卡数相加，不估算），并给一句热量点评：
  - 用户说"减脂/轻食/低卡/健身"→ 同价位优先低卡组合：主食选 M7 蔬菜鸡蛋堡(350) 或 M5 香辣鸡肉卷(420)，小食优先 S6 蔬菜沙拉(120) 而非薯条，饮料优先 D4 热美式(10)/D6 矿泉水(0)；
  - 用户说"管饱/饿了/增肌"→ 优先高卡高蛋白：M10 咖喱鸡腿饭(620)/M11 卤肉饭(650)/M12 香菇滑鸡饭(600) + S3 黄金鸡米花(380)；
  - 未提热量 → 三档各给一个热量档位，让人自己选。
- 每档输出一张迷你小票（明细 ×数量 金额 + 合计 + 合计千卡 + 为什么这么配一句话）。
- 忌口同样适配：提到不吃辣/素食等，按合同忌口组逻辑筛品项。
- **接入麦当劳 MCP 时**：若当季有活动/新品，在吃好档优先展示并标注"当季活动/新品"（以 MCP 实时数据为准，不虚构活动）。
- 三档合计都不得超 B；预算过低（B < 单人保底 15.5 元）时如实说明并转合同第 9 步"点不成"流程。

### 3B. 模式B · 麦门省钱

- 输入：想吃的品项清单 + 预算上限 B。
- 第一步按原话全价算一遍（原方案金额 P0）；然后用三招压价：
  1. **等价替代**：口味档位不变的保底款替换（香辣鸡腿堡→香辣鸡肉卷类）；
  2. **分享装合并**：多人同类小食合并为分享装（2×中薯条 22.0 → 1×大薯条 14.0）；
  3. **免费项顶上**：饮料换免费柠檬水、矿泉水降级等。
- 每一招先列出"动了什么、省多少"，压到预算内即停，不牺牲用户点名要吃的核心品项。
- 输出对比小票：`原方案 P0 元 → 省后 P1 元，省 (P0−P1) 元`，附逐条省钱依据；仍超预算则报告最小不可让步清单。

### 3C. 模式C · 聚餐一键点（九步算法）

- 解析需求（口径与离线网页版解析器一致）：
  - **人数 N**：支持中文数字（"六个人"=6）与阿拉伯数字；勿把人数误读成其他数字。
  - **预算 B**：区分"一共/总共 B 元"（总预算）与"人均 B 元"（总预算 = B×N），勿混用。
  - **忌口归组**——主食桶（互不重叠，合计 ≤ N）：素食 V / 不吃辣 S / 不吃猪肉 P；饮料桶：不喝冰饮 I / 不喝咖啡因 C；其余（过敏等）一律写备注：
    - "吃不了辣/不敢吃辣/怕辣/辣的都不能吃"→ 不吃辣组；"不吃肉/不吃荤"→ 素食组；"清真"→ 不吃猪肉组；"不喝茶/不喝咖啡"→ 不喝咖啡因组；"怕凉/不喝凉的"→ 不喝冰饮组。
    - "有人 X"按 1 人计；"全员 X / 都不吃 X"按全部 N 人计（不是 1 人）。
    - 一人多忌口时主食归最严格组（素 > 不吃辣 > 不吃猪肉），其余需求写备注。
    - **过敏类信息只进备注、不当普通忌口处理**（上甜品前必须先查备注）。
  - 未报项目按 0 处理。
- 按合同第 1—9 步顺序执行：保底主食 → 矿泉水 → 忌口组升级 → 常规组升级 → 饮料升级 → 共享小食（N≥3）→ 豪华升级（过门槛才启动）→ 收口自检 →（预算不足时）"点不成"流程。
- 每步先列算式再写结果，全程记录金额流水（①—⑦ 固定七行，未发生/跳过的阶段同样占行并注明原因，零花费记"—"）。
- 输出合同规定的小票样式：明细（品名 ×数量 金额）、合计/人均/结余/人均能量、预算流水、拆解（常规组＋各忌口组）、逐条"为什么这么点"、自检清单。
- 标准回归用例：6 人 · 150 元 · 2 人不吃辣 → 总价 148.0、结余 2.0（合同末尾附完整复算过程，可对照验证执行结果）。
- 预算不足（B < 保底合计）时走第 9 步：如实报告差额、给出最省点法与二选一建议（补预算 / 减 1 人；N=1 时只建议补预算）。

## 菜单替换

默认使用合同内固定菜单；接入麦当劳 MCP 后以实时菜单为准。用户自带菜单/价目表时：九步算法与四条铁律不变，按同样结构替换品项、价格、各组保底款与升级款（须为每组忌口指定合规替代品），并向用户明确说明替换后的口径。
